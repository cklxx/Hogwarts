# 服务器存档与恢复

`npm start` 每 30 秒尝试一个检查点。世界和已启用的使魔状态先在同一个同步调用中序列化，再异步写盘。磁盘忙时复用当前任务，不排队积累更多世界副本。JSON 序列化仍在主线程执行。

每个文件先写入同目录的唯一临时文件（权限 `0600`），同步文件字节并关闭，再原子替换目标。写入或替换失败保留原目标，清理当前临时文件；之后的周期可以重试。世界和使魔文件分别替换，**不是跨文件事务**；文件同步也不等于所有文件系统上的断电恢复保证。请保留独立备份。

## 启动

- 只有存档不存在才创建新世界。
- 世界存档 JSON 损坏、读取失败、格式版本不支持或基本时间／身份字段无效时，停止启动，不改写存档。已有的无版本／v1 存档仍走原迁移逻辑，当前格式为 v2。
- 启用使魔时，使魔存档也必须能读取和恢复；损坏的配额不能静默清零。未启用使魔时不读取其文件。
- 存档读取和进程级故障的诊断包含文件位置或异常调用位置，不输出存档内容或异常消息中的用户输入。

遇到启动失败，先复制故障文件到安全位置，再从自己的有效备份恢复。服务器不会自动猜测哪个旧文件正确。确实要创建独立新世界时，将 `HOGWARTS_DATA` 指向新位置。

## 退出

`SIGINT` / `SIGTERM` 停止世界时钟、广播和新连接，结束 Agent 工作；等当前写盘结束后，再保存最终状态。使魔停止前保留其召唤关系和已用配额。完整检查点成功才以 0 退出；写盘失败或等待超过 10 秒以 1 退出，不报告保存成功。

未捕获异常和未处理 Promise 拒绝视为进程级故障：立即以 1 退出，**不保存可能只更新了一半的世界**。请求级的正常输入错误继续由各协议处理，不走这个路径；格式错误的 URL／JSON 返回 400，JSON 解析器的输入片段不进日志或回复。`REALMS` 的父进程会重启故障 worker；单进程部署需要自己的进程管理器或手动重启。故障会丢失上次检查点之后的未保存进度，正常情况下约一个 30 秒周期，慢盘或写盘失败时可能更久。

## 验证与测量

`test/server-recovery.e2e.test.ts` 在独立临时目录启动真实服务器，覆盖坏文件、未来版本、异常／拒绝、正常保存、真实文件替换失败、使魔状态和退出超时。故障注入通过测试进程的 preload 完成，生产服务器没有注入开关。`test/persistence.test.ts` 覆盖旧格式、关键字段损坏、字节一致性、权限、慢盘合并请求和最终检查点。

`npx tsx scripts/bench-persistence.ts --n=500,2000 --rounds=9` 交替测量旧同步写法与新实现，使用同一静止世界并逐次核对保存字节。结果含主线程同步阻塞、下一次事件循环机会和完整写入时间；不输出身份或密钥。最新结果见 [PERF](PERF.md)。真机 GPU／手机和小时级持续负载仍是单独的验收。
