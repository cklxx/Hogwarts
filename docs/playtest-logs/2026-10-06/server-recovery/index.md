# 服务器存档与故障恢复回归

2026-10-06，基线 `308cbda`，实现 `2781f0c`。这轮是代码可靠性改进、真实服务器故障注入和性能对照，不另计一小时试玩。

## 问题与结果

旧服务器在坏存档上启动新世界，下一次保存会替换原文件；未捕获异常／未处理拒绝只记录错误，然后继续运行，异常路径还会保存可能半更新的世界。先写的五项真实进程回归在基线上四项失败（坏文件和未来版本仍启动；两种致命异常未退出，测试超时），正常信号保存一项通过。

新实现将存档处理与时钟／生命周期从 `server/main.ts` 拆出：

- 只有文件不存在才新建；世界的旧格式继续迁移，坏 JSON、无效基本字段和未来版本停止启动，原文件不变。
- 启用使魔时也检查其存档，不因损坏清零配额或忘记召唤关系。
- 进程级异常立即退出，不保存半更新状态；日志保留调用位置，省略可能含用户输入和密钥的错误消息。
- HTTP 和 WebSocket 升级的无效 URL 在请求边界返回 400，不触发进程级退出；基线两项真实请求均超时，修复后错误请求之后仍能正常读取规则。
- 坏 JSON 返回统一的 400，不打印或回传解析器的输入片段。原行为两项测试得到 500，修复后入学和 MCP 两个入口都不回显夹具私密值。
- 自动存档先冻结两份序列化数据，异步写盘并同步文件字节后替换，各文件权限为 `0600`；只允许一项写盘任务，慢盘不累积世界副本。
- 正常信号停止时钟／广播／连接和 Agent 工作，等待旧任务并再次捕获最终状态；保存成功才以 0 退出，失败或超过 10 秒以 1 退出。

## 验证

新增 **28 项**回归：真实进程十三项，存档模块十五项。包括正常保存恢复、旧格式、重复身份／凭据、无效时间／位置、真实文件替换失败、慢盘合并、最终保存重试、使魔召唤关系和已用配额、故障日志不含夹具私密值、退出超时、无效 URL 的请求隔离及坏 JSON 不回显私密输入。

第一轮全量 **91 文件、944 项测试**通过；追加无效 URL 回归和保留时钟／广播顺序后的 946 项通过，再追加坏 JSON 两项保护，最终代码 **91 文件、948 项测试**、类型检查及生产构建全部通过。本轮未修改内核规则、常量或形式化模型，已有形式化对照测试包含在全量测试中；完整 TLA+/Lean 检查由 PR CI 执行。

## 性能与限制

使用 Node 24.19.0、Linux、5 核可见 AMD EPYC 7763 环境。保存微基准在同一静止世界中交替九轮，另有三轮预热，每次严格核对前后保存字节；测量包含原有 `World.serialize()` 和 JSON 序列化。500 人约 1.56 MB、2000 人约 6.23 MB。

| 角色数 | 主线程同步阻塞中位数，旧→新 | 下一次事件循环机会，旧→新 | 完整保存中位数，旧→新 |
|---:|---:|---:|---:|
| 500 | 5.54 → 5.16 ms | 5.55 → 5.17 ms | 5.54 → 6.73 ms |
| 2000 | 26.93 → 23.62 ms | 26.96 → 23.71 ms | 26.94 → 27.99 ms |

收益是减少同步文件操作造成的阻塞；新实现额外同步文件字节，完整写入略长。JSON 序列化仍占主要同步成本，这些微基准不代表整个游戏的 FPS 或吞吐。

200 客户端真实 HTTP／WebSocket 对照使用每人 20 Hz 输入、每秒一次施法、二进制区域快照、单 realm，Node `--max-semi-space-size=64`。首轮前后各采样 60 秒、预热五秒，均保持 200/200 连接、施法回复 100%。首轮广播和施法尾延迟上升，后续交替复测保留所有结果，不以一次差值宣称整体性能提升。
