# Hogwarts 手机新手真实试玩（PhoneNova）

2026-10-03，`http://127.0.0.1:7777/?view=top`，Chromium 软件渲染，390×844 触屏。使用仓库 `scripts/playtest/phone.mjs`，端口 7911，截图目录 `/tmp/hogwarts-phone-newbie`。每步读取实际屏幕文字，并在关键决策前通过 `view_image` 查看画面；没有依据源码假装游玩。没有修改仓库源码。结束时已关闭该手机 driver 与其浏览器以释放性能测试资源。

## 做成了什么

成功入学 PhoneNova（斯莱特林），摇杆移动，第一发昏昏倒地命中小精灵并掉落分裂符文，触摸装备到昏昏倒地，跟随「带我去」进入礼堂安全区，打开咒语书，将元素弹威力从 14 调低至 4 并铸造到 6 号快捷栏，施放时间显现，尝试 Agent 配对后选择以后再说，关闭菜单，施放自铸元素弹、移动、翻滚、治疗。与 ExplorerAsh 同处小精灵区域，未主动聊天；这轮目标是基本操作，不计社交表现。

引导看到了 1/8→6/8；在 6/8 选择「以后再说」后引导完全隐藏，没有观察到 7/8 或 8/8。不能声称完整完成全部引导。没有确认打倒第一只魔物；第一击和符文掉落有明确反馈。年级/声望/加隆/学院分未展开查看，不编造数字。

## 可复现体验问题

### P1：首次符文阅读时持续受伤，且卡片遮挡指引

步骤：新角色前移到小精灵→点第一发昏昏倒地→首次分裂符文卡弹出→停留阅读或误触卡正文。

实际：中央窄卡片遮挡角色与下一步引导；小精灵继续攻击。s0004 响应显示玩家 97/100 HP，阅读后一次正文误触 s0005 已到 52/100。之后 s0006 血量回到 90 附近，但我没有观察到可靠死亡/复活事件，所以不判定死亡。盯着卡片时无明显移动教学或收起入口。

期望：首次掉落的教学可快速理解和收起；新手能看到当前风险并立刻离开战斗。是否保护玩家属于规则设计，应保留多人公平，不能凭此报告直接永久免伤。

证据：[首次卡片](screenshots/phone-rune-before.png)、[血量下降](/tmp/hogwarts-phone-newbie/s0005.png)、[装备后](/tmp/hogwarts-phone-newbie/s0006.png)。

### P1：手机「时间显现」时钟与姓名条重叠，时间不可读

步骤：在礼堂按第 5/8 步「施放」→时间显现→关闭其他菜单后观察左上角。

实际：宽约 270px 的羊皮纸时钟贴到左上角，姓名/学院徽章盖住第一行，时刻数字在可见画面中不可读，只剩倒计时较清楚。DOM 文字存在 21:53 / 1:19，但截图只清楚看见 1:22（截图时刻与文本捕获略有延迟）。引导称点亮右上角，但手机实际在左上。

期望：移动端时钟避开姓名栏，时间和倒计时都完整可读，并与提示方位一致。

证据：`screenshots/phone-clock-before.png`、`s0018.png`、`s0022.png`。

### P2：长菜单缺少始终可见的退出入口

步骤：第 6/8 步生成配对码→菜单跳到配对卡区域→选择「以后再说」→尝试点菜单外侧。

实际：菜单占据几乎整个手机屏幕，当前滚动位置没有关闭按钮，边缘点击也无效；底部「回到城堡」需继续滚动才能到达。驱动需根据已返回的屏幕文本，调用该按钮 ID 并自动滚动后才关闭。

期望：菜单固定顶部有清楚的关闭入口，或跳过配对时回到游戏。未经真人滑动验证，不能认定完全无法退出，只能认定当前视口无易发现退出方式。

证据：`s0014`–`s0017` 含临时配对码，不建议放入公开 PR；可重新生成无凭证的菜单截图用于公开报告。

### P2：新手指引在窄屏大量省略正文

步骤：看 2/8 战斗提示、3/8 礼堂提示、6/8 Agent 接入提示。

实际：例如「点小精灵（或准星）选它，再点 1 ↑ …」「去大礼堂（安全区）↓大…」「连上你的…」。靠按钮和动作能继续，但正文不完整；6/8 选「以后再说」后整条引导消失，此次未看见后续步骤。后者可能是产品设计，需要确认。

证据：`s0003.png`、`s0006.png`、`s0013.png`、`s0018.png`。

## 测量与限制

- 20 次交互，其中 1 次误点符文正文、1 次点菜单边缘无效。滚动导航通过驱动自动滚动，不能算真实手指滑动表现。
- 入学、移动、第一击、打开咒语书均有真实响应；单次 HTTP 操作含截图通常 10–20 秒，末尾翻滚调用约 45 秒。当前三名 Agent 并行软件渲染，这是测试基础设施成本，不可当成客户端输入延迟或真实手机 FPS。
- s0002 捕获在入学过渡动画中，画面明显变暗，后续恢复；没有证据证明黑屏故障。
- 不能给可信真人首次移动/施法秒数；可以由服务端 metrics 补充事件时间，但仍受 Agent 思考和共享 CPU 污染。
- 没有测 SUS、趣味性、推荐意愿；Agent 的分数不能代替真人。
- 引导实际显示 8 步，PLAYTEST_METRICS 文档仍写 7 步，指标口径应同步。

## 第二轮：修复后真实手机回归

同日最新 build、重启后的 7777、独占 Chromium 软件渲染窗口，390×844，新角色 PhoneNovaTwo。沿真实入学流程完成 18 次交互，未写入 state、未改 clock、未用内部 API 跳过战斗/掉落/引导。浏览器结束后已关闭，并将窗口交给桌面 Agent。

### 核心回归结论

1. **首次符文卡通过**：第 5 次操作真实首击后掉落分裂；第 6 张截图清楚显示卡片宽约 374px、高约 130px，三个可触按钮横排，符文说明清楚；第 3/8 引导在卡片上方，两者不重叠。第 7 次操作点击「装 昏昏倒地」，卡片关闭，快捷栏出现分裂图标。修复前证据 `screenshots/phone-rune-before.png`，修复后安全证据 `screenshots/phone-rune-after.png`、`s0007.png`。仍会受到敌人攻击，75→28 HP 的变化保留；本轮没有改变公平规则，也不宣称已解决读卡期间受伤。卡已装备，未额外开新角色重测「符文代码」展开/收起，此分支未覆盖。
2. **Tempus 时钟通过**：第 12 次操作通过引导真实施放时间显现，手机右上紧凑显示 `13:00` 等时刻，数字不再被姓名栏遮挡。第 14、15 次操作两次点时间按钮，都能显示当前时间、天气、学期、剩余时间；连续更新期间触摸目标仍可操作。没有做 DOM 节点 identity 的白盒断言，因此“节点稳定”仅有连续真实点击可用的行为证据。修复前 `/tmp/hogwarts-phone-newbie/s0018.png`，修复后安全证据 `/tmp/hogwarts-phone-regression/s0014.png`（13:35 时钟、13:30 时刻的详情 toast；差值来自模拟时间更新与截屏耗时）。
3. **Later 通过**：第 16 次操作真实生成配对码打开菜单，第 17 次操作点顶部「以后再说」，菜单立即退出到游戏并显示 8/8 旅行提示；第 18 次操作点「知道了」，返回「引导完成，玩得开心！」。安全证据 `screenshots/phone-travel-after.png`、`s0018.png`。含配对码的 s0016 图片已删除，工具未输出凭证文字。未实际配对 Agent，因此 7/8 成功接入分支不属于本轮覆盖。

### 18 次操作顺序与边界

入学 → 前移（期间恰逢学院杯弹窗，未推进）→ 点关闭学院杯 → 再前移 → 第一击 → 点场景空白（首卡刚出现时尚未看清）→ 装备符文 → 带我去 → 等待导航 → 打开书 → 关闭书 → 施放 Tempus → 点 toast 空白（误点）→ 点钟显示详情 → 再点钟刷新详情 → 生成配对码 → Later → 知道了。

仍保留前轮问题：窄屏引导正文省略较多；首次符文阅读仍遭敌人攻击。此轮已确认所要求的三个核心 UI 回归通过，不扩展其他系统。
